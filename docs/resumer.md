# ClaudeResumer — 對話接續排程器

> 某個對話被 session limit 卡住了。你知道幾點會恢復，但不想守在電腦前面。
> 把時間設給它，時間一到它會自動把那個對話接著送出去。

用完就關掉，不常駐、不需要安裝。

---

## 一次完整流程

Claude Code 跳出 `You've hit your session limit`、告訴你大概幾點重置時：

### 1. 打開 `ClaudeResumer.exe`

（或 `.venv\Scripts\python resumer.py`）

### 2. ① 選哪一個對話

清單列出本機的對話，最近活動的排在最上面。七個欄位：

| 欄位 | 是什麼 |
|---|---|
| 最後活動 | `3 小時前` 這種相對時間 |
| 專案 | 那個對話所屬的資料夾名稱。**兩個不同地方同名時會帶上一層資料夾**（`work/WebApp`、`play/WebApp`） |
| 分支 | 對話當時所在的 git 分支——分身（worktree）跟主專案同名時靠這個 |
| 對話標題 | Claude Code 自己給那個對話的標題（你有自訂就用自訂的） |
| 最後一句 | **你最後一次跟它說的話**——被卡住的對話通常靠這個最好認 |
| 來源 | 從哪開的：`VSCode`、`終端`、`程式(-p)`（ClawBot、探針這類用 `claude -p` 開的）；前面再標 `分身·`＝worktree |
| 狀態 | `● 開啟中` 代表現在正被開著（見下面的鐵律） |

為什麼要有「來源」：同一台電腦上 ClawBot 的 AI 秘書、各種探針、resumer 自己的 `new` 都用
`claude -p` 開對話，資料夾叫 `agent_workspace`、`scratchpad`、一串 hex，全部混在一起就是
「一堆同名專案不知道哪個是哪個」。**「藏起暫存與程式用的」預設勾著**：暫存資料夾（`TEMP`）
與程式自己工作區（`LOCALAPPDATA` 底下）的對話不列；要找它們就取消勾選。

上面的「篩選」框可以打字比對專案路徑、標題、最後一句、分支。預設載入最近 200 個對話，
不夠的話按「載入更多」。選起來之後，「已選」那一行會寫**完整路徑與分支**，同名專案靠這行確認選對了。

### 3. 不確定是不是這個？先看內容

**雙擊那一列**（或選起來按「查看內容」）會開一個唯讀的預覽視窗。只讀本機檔案，
**不花任何 token**。人認對話靠的是「我當時說了什麼、它最後回了什麼」，所以畫面**一輪一輪**排：

```
第 5 輪｜10-08 03:35
你        continue
　▸ 中間過程：⚙ Bash ×5、Read ×2、Edit ×2｜中途回覆 2 則      ← 預設收起來，點一下才展開
Claude    最後回覆
          做完了，七點都完成。……（整段）
```

- **這個對話在做什麼** — 期間、歷時、幾輪、各類訊息則數、常用工具，以及**最後一次你說了
  什麼 / 它回了什麼**。通常看這裡就夠了。
- **左邊大綱** — 每一輪你說的第一句，點一下跳過去。
- **右邊內容** — 你說的整段 → 收起來的中間過程 → 它最後回的整段。沒有回覆的那一輪會標
  「可能就是卡在這裡」。很長的對話只有最近 10 輪預設展開，更早的一行一輪、點了才展開；
  超長的訊息先摺起來，按「展開全文」。

下方那排：

- **搜尋** — 只留下含有那段文字的輪，命中處反白，而且那幾輪的中間過程會自動展開。
- **全部展開中間過程** — 想一次看完所有工具動作時用。
- **展開時連思考也顯示** — 預設不顯示（那通常是雜訊）。
- **跳到最新** — 跳到最後一輪，也就是被卡住的地方。

確認是對的就按「**就選這個對話**」，會直接回主畫面幫你選好。

### 4. ② 時間到要送出什麼

| 欄位 | 說明 |
|---|---|
| 接著送出的內容 | 預設 `continue`（＝請它接著做下去）。可以自己改；「附加檔案」會用 `@路徑` 的寫法加進去 |
| 送出時間 | 填 Claude 告訴你的重置時間。吃 `HH:MM` 或 `HH:MM:SS`；已經過了今天那個時間會自動算成明天。旁邊有「＝現在」「+1 分」跟即時時鐘，勾「精準到秒」可以測試時不用等整分 |
| 送出方式 | **自動送出**（建議）＝時間一到直接送；**時間到只提醒我**＝到點只標記，等你按「立即送出」 |
| 被佔用時 | 時間到了那個對話還被開著要怎麼辦，**排程時就講好**：見下面「被佔用怎麼辦」 |
| 權限模式 | 見下面「權限模式」 |

按「**加入排程佇列**」。可以一次排好幾筆。

### 5. ③ 排程佇列

排好之後這支程式要**保持開著**（它就是那個計時器）。時間到會自動送出，狀態列與
「狀況 / 錯誤」欄會即時說明發生了什麼。

- **移除選取** / **立即送出** — 顧名思義。
- **改成「到時接管」** — 把已經排好的那筆改成「時間到若還被佔用就接管後送出」（等於 ② 的第二個選項）。
- **立刻接管並送出** — **現在**就關掉開著那個對話的行程、馬上送，不等排定的時間。見「被佔用怎麼辦」。
- **全部送出後自動關閉視窗** — 預設勾著（全部確認送出後 3 秒自動關）。想留著看結果就
  取消勾選。**只要有任何一筆失敗就一定不會自動關**，否則看不到失敗原因。

## 鐵律：送出的那一刻，那個對話不能開著

Claude Code 的一個 session **同一時間只能有一個持有者**。如果送出時那個對話還開在
VSCode（或任何地方），`--resume` 會回 `Session ID ... is already in use` 然後秒退，
等於白送。

這支工具會在**不花任何 token** 的前提下自動處理這件事：

1. 每個正在跑的 Claude Code 行程（含 VSCode 擴充）都會在 `~/.claude/sessions/<pid>.json`
   寫下自己現在開著哪個對話、行程的建立時間、閒置還是忙碌。工具讀這些檔就知道誰被佔用了——
   清單上標 `● 開啟中`，描述會寫「閒置中（最後動作 4 小時前）」或「正在跑」。
2. 送出時如果偵測到被佔用，**不會白送**：那筆任務會被擋下、標成「被佔用」。
3. **自動送出模式下，你一把 VSCode 那個對話關掉，下一秒它就自己補送**，不用重排。

那個 `<pid>.json` 在行程結束後不一定會被清掉，而 pid 又會被作業系統重用：v1.3.0 之前只看
「pid 活著而且叫 claude」，VSCode 開關幾次之後，一個早就關掉的對話會一直顯示被佔用、怎麼關都
釋放不了。現在要跟檔案裡的行程建立時間對得上才算持有者，殘留檔直接忽略。

### 被佔用怎麼辦

Claude Code 的鎖是「誰的行程還活著誰持有」，沒有禮貌接管的辦法，只能讓現在的持有者結束。
所以每一種「搶」都是**破壞性**的：被關掉的那個對話在 VSCode 裡沒存、或正在跑的東西會一起沒掉。
你有四種做法，差別在**什麼時候動手**：

**v1.4 起，接管有兩條不會越過的線**（CLI、Python API、視窗都一樣）：

1. **正在跑的不從中間砍斷**。「時間到就強制接管」到點時，持有者如果是「正在跑」，就**不關**、等下一次重試，
   等到它停下來（例如額度用完、它自己做完）才接管。你平常的用法——等 token 用完再接管——完全照舊；
   擋掉的是 2026-10-15 那種「還在做事就被關掉」。你自己按的「立刻接管」「釋放佔用」看得到狀態，所以可以關正在跑的。
2. **程式開的不碰**。持有者不是 VSCode／終端機（是 `claude -p`：PipelineAgent 的節點、另一筆 Resumer 工作），
   一律不關、等它結束再補送。那些有自己的主人在追蹤，從這裡殺掉，那邊會看到一段莫名中斷的 session。

關的時候連它的子程序一起收（`taskkill /T`）：它開的 bash、背景跑的測試、它自己起的伺服器不會變成沒人管的孤兒；
收掉了什麼會寫在訊息裡。接管之後送出的那句前面會多一段說明，讓接手的那個知道自己的處境（背景執行、權限是什麼、
被擋住就停下來把狀態寫清楚）。

| 做法 | 什麼時候動手 | 在哪裡 |
|---|---|---|
| **等它關掉再補送**（預設） | 不動手。你關掉那個對話，下一秒自動補送 | ② 被佔用時 · 第一個選項 |
| **時間到就強制接管** | 到了排定的時間還被佔用，才關掉持有者、送出 | ② 被佔用時 · 第二個選項；或 ③「改成到時接管」 |
| **立刻接管並送出** | **現在**就關掉持有者、馬上送，不等排定的時間 | ③ 的紅色按鈕（趕時間才用） |
| **釋放佔用（不送出）** | 現在就關掉持有者，**不送任何東西** | ① 的紅色按鈕；CLI `release` |

「釋放佔用」是給「我這個對話用完了、關掉 VSCode 它卻還顯示被佔用、我只想把它清掉」用的：
清完之後排程照原本的時間送。

**對話框可以留著不關嗎？** ② 的第三個選項「分支接續」用 `claude --resume <id> --fork-session`：
不搶佔，接續的那一段續在一個**新的對話 id** 底下，原本的對話框照舊開著。代價是接續的內容
**不會出現在原本的對話框裡**，而且**這條路還沒在真的 claude 上驗證過能不能繞過鎖**（claude 2.1.293
有這個旗標；若它仍然要求原本的 session 沒被開著，那筆會跟平常一樣失敗，不會多花錢）。試過之後
請回報結果，文件再改。

### 送出前想先確認

選起來按「**檢查可否送出**」：一次檢查 claude 執行檔找不找得到、對話紀錄檔還在不在、
專案資料夾還在不在、**以及現在有沒有被佔用、佔用的那個閒置多久了**。全部不花錢，免得等到半夜時間到才發現。

## 權限模式

接續是 `--print` 的**非互動**執行，**沒有人能回應中途的權限提示**——而且那個行程不在
VSCode 裡，也不會跳到 VSCode 讓你按。所以如果那個對話接下來需要工具權限確認，它可能
就停在那裡不動。

| 選項 | 意思 | 什麼時候用 |
|---|---|---|
| `(沿用原本)`（預設，v1.4） | 照那個對話**最後一次在 VSCode／終端機裡**的權限模式、模型、effort（從對話紀錄讀） | **幾乎都是這個**：你在 VSCode 開 auto，接手的就是 auto |
| `auto` | 分類器代替你按同意：一般的放行、危險的擋下 | 睡覺時讓它接著做 |
| `acceptEdits` | 自動同意「改檔」類的權限；指令還是要在白名單裡 | 只改檔、不太跑指令的接續 |
| `dontAsk` | 不主動詢問權限 | 不確定就選上面兩個 |
| `plan` | 只規劃、不實際動手 | 只想讓它接著想、還不要真的執行 |
| `bypassPermissions` | 略過所有權限檢查，什麼都不問（含執行指令） | 完全信任那個對話接下來要做的事時；「沿用原本」**永遠不會**自己選它 |
| `(不覆寫)` | 不加參數＝headless 的預設（default），**不是**沿用原本的 | 幾乎不要選：要權限的工具沒有人能按同意 |

**為什麼預設要「沿用原本」**：VSCode 裡的 auto 不是存在設定檔的東西，是那個互動行程的狀態。`claude --resume --print`
起來的是另一個行程，不帶參數就是 default：白名單以外的指令、工作目錄以外的檔案一律被拒。2026-10-15 那一晚就是
這樣——接手的兩個對話都在第一個 `git` 就停住。對話紀錄每一句都記著當時的 `permissionMode`、每一則回覆記著模型與
effort，所以照著帶就好；接管跑出來的那幾段（`sdk-cli`）不算，`bypassPermissions` 不沿用（改用 `auto`）。

**做了什麼看結果，不看 exit code**：送出時一律要 `--output-format json`；它結束後佇列寫「完成（12 輪、$0.84）」或
「完成，但被權限擋了 3 種：Bash(git fetch)…」——後者代表它多半停在那裡，要你決定要不要放行。

## 常見問題

**關掉 resumer 之後，那個對話還會跑完嗎？**
會。送出的是一個獨立行程（`DETACHED_PROCESS`），不是這支程式的附屬子行程。確認送出
（撐過 60 秒）之後就可以關掉本工具，被接續的對話會在背景自己跑完。輸出寫在
`%LOCALAPPDATA%\ClaudeTimerResetter\resume-<id>.log`。

**跟我平常在 VSCode 裡用的 Claude 是同一個嗎？**
對話記錄是同一份。VSCode 擴充跟 CLI 共用 `~/.claude/projects/<專案>/<id>.jsonl`，
`--resume` 是往同一個對話檔接著寫（實測不會分岔成新檔），所以事後回 VSCode 打開那個
對話，**看得到接續之後跑的那一段**。執行檔通常也是同一支——找 claude 的順序最後一項
就是去撈 VSCode 擴充裡那支 `claude.exe`。

**背景在跑的時候我開 VSCode 會不會把它弄斷？**
真正「在送」的那一瞬間很短（就是送出的那一下）。撐過確認期之後看到的都是已經寫進
對話檔的結果，回 VSCode 開來看不會把它弄斷。保險起見，**送出中～確認完成前先別搶著
開那個對話**就好。

**「送出成功」是怎麼判定的？**
送出後盯那個行程 60 秒：撐過去就當作送出成功（剩下的讓它在背景跑完）；60 秒內就死掉
的標成失敗，並把紀錄檔尾巴印在「狀況 / 錯誤」欄裡。

**它會不會自己判斷「其實還沒重置」而不送？**
不會，這是刻意的。你在這裡設的時間就是最終決定，這支工具不查用量、不做二次確認。
會去算時間、決定要不要打的是另一支工具（resetter），兩者的差別見 [design.md](design.md)。

## 疑難排解

| 現象 | 多半是 | 怎麼辦 |
|---|---|---|
| 時間到了，狀態變「被佔用」 | 那個對話還開在 VSCode | 關掉它或按「釋放佔用」，自動模式下一秒就補送；下次排程時選「時間到就強制接管」 |
| 關掉 VSCode 了還是顯示「開啟中」 | 殘留的 `~/.claude/sessions/<pid>.json`（v1.3.0 起已經會比對行程建立時間，應該不會再發生） | 按「重新整理」；還在就按「釋放佔用」，並回報 |
| 失敗，訊息說 `找不到 claude 執行檔` | 那台電腦沒裝官方 Claude Code，或沒在 PATH 上 | 裝好並登入過一次 |
| 失敗，紀錄是空的 | 幾乎都是 session 被佔用 | 先用「檢查可否送出」確認 |
| 清單裡找不到那個對話 | 預設只載入最近 200 個；或它在暫存／程式用的資料夾裡被藏起來了 | 按「載入更多」、取消「藏起暫存與程式用的」，或用篩選框找 |
| 清單裡好幾個同名專案 | 不同地方的同名資料夾、worktree 分身、程式開的對話 | 看「專案」帶的上一層資料夾、「分支」與「來源」欄；選起來看「已選」那行的完整路徑 |
| 送出後對話沒有動靜 | 卡在權限提示 | 權限模式改 `acceptEdits` 重排一次 |

畫面上的每一則訊息也會寫進 `%LOCALAPPDATA%\ClaudeTimerResetter\resumer.log`，
排在半夜的任務隔天早上可以回來查。
