# ClaudeTimerResetter — 提前重置排程器

> 在你預期會重度使用 Claude「之前」，先把 5 小時額度視窗的重置時鐘催起來。

## 它在解決什麼

Claude 的額度是 5 小時一個視窗。重度工作常常 2~3 小時就把額度用完，然後撞牆乾等——
而且往往卡在最需要它的時候。

關鍵是：**5 小時的倒數是「第一次呼叫」那一刻才開始跑的**，不是整點對齊的。所以只要
在你真正開始工作之前，先送出一次極便宜的呼叫，倒數就提早開始；等你用到額度見底時，
下一輪重置剛好接上，工作不會被打斷。

這支工具就是自動幫你在指定的時間點做那一次呼叫。單次成本約 **$0.00025**、約 4 秒。

---

## 怎麼用

雙擊 `ClaudeTimerResetter.exe`（或 `.venv\Scripts\python resetter.py`）打開主控台，
由上到下三步：

### ① 什麼時候要刷新

按「新增規則」。一條規則就是一組觸發時間點，可以同時放好幾條，各自獨立判斷、互不影響。
對話框下方會即時顯示這條規則的白話意思，加入前可以先確認。

| 規則類型 | 什麼時候用 | 例子 |
|---|---|---|
| **每天固定幾個時間點**（建議） | 你知道自己大概幾點開始用 | `05:00, 10:00, 15:00, 20:00` |
| **每隔 N 分鐘一次** | 整天都可能在用，不想算時間 | `480`（每 8 小時） |
| **某時刻之後連續重試** | 額度大概那個時間前後才會恢復 | `06:00` 起每 `15` 分鐘，最多 `5` 次；或改成「直到成功為止」 |

**時間點怎麼抓**：觸發時間的意思是「**預估到這個時候額度差不多要用完了，該催下一輪
重置**」，不是「這個時間點才開始工作」。所以要抓提前量。實務例子（兩個帳號各自一組）：

- 公司帳號在上班時段重度使用，提早 2.5 小時預熱 → `05:30, 10:30, 15:30, 20:30`
- 個人帳號是工作空檔才用，提早 1 小時 → `07:00, 12:00, 17:00`

（「直到成功為止」的「次數上限」是防呆用的安全上限，避免探針一直失敗時整天無限重打。）

### ② 用哪種方式在背景執行

| | 工作排程器（建議） | 工具列常駐 |
|---|---|---|
| 怎麼跑 | 註冊進 Windows Task Scheduler，**到點才把程式叫起來跑一次**，跑完就關 | 小圖示留在工具列，靠內部計時器到點觸發 |
| 要開著視窗嗎 | 不用 | 要（程式得一直活著） |
| 管理員權限 | 不需要 | 不需要 |
| 可靠度 | **高**。沒有長命行程可以當掉，每次觸發都是全新一次；睡眠或剛開機錯過的時刻會盡快補跑（`StartWhenAvailable`） | 較低。單一長命行程，當掉就停擺到下次重開機 |
| 另外提供 | — | 右鍵選單：開啟主控台 / 立即測試 / 結束程式 |

除非你就是想要一個看得見的圖示，**建議用工作排程器**。

兩種方式互斥：切換時安裝器會自動把另一種的殘留（排程項目、開機捷徑、常駐行程）
清乾淨，不會兩邊同時打。

有 `daily_times` 規則時，排的是那幾個時刻的觸發器（不是每分鐘輪詢），每個時刻外加一個
30 分鐘內每 10 分鐘的小重試窗，用來 cover「觸發那一刻剛好接近重置、這次先退回」的
邊界；那幾次補跑通常是「查一下發現已經做過了」的次秒級動作，不打 API、不花錢。

### ③ 套用

- **安裝／更新設定**：把規則存檔並套用執行方式。exe 會把自己複製到
  `%LOCALAPPDATA%\ClaudeTimerResetter\`，之後背景跑的是那一份，原本下載的那份可以刪。
  改完規則要再按一次才會生效。
- **立即測試一次**：走的是跟排程完全一樣的那條路——已經刷新過就不會再打，**按幾次都
  不會多花錢**。
- **解除安裝**：移除排程項目、開機捷徑、常駐行程，以及安裝資料夾裡的設定與紀錄。
  清完把你當初下載／建置的那份 exe 刪掉，系統上就不會留下任何東西。

> 從原始碼跑的時候按「安裝」會被擋下來：安裝需要 exe（要有東西可以複製過去、
> 給排程器呼叫）。先跑 `scripts\build.bat`。

## 什麼時候才真的打

它不是無腦打一次 API。每次觸發都先花 0 元查一次用量，再決定要不要花那 $0.00025：

| 5 小時視窗的狀態 | 做什麼 | 為什麼 |
|---|---|---|
| 還沒開始計時（`resets_at` 是 `null`） | **打** | 打下去重置時鐘才會開始跑，這正是這支工具的目的 |
| 再 15 分鐘內就要重置 | **等它重置完再確認一次才打** | 現在打是打在舊視窗上，等一下就白花了 |
| 已經在跑而且還早 | **不打** | 重置時鐘早就啟動了，再打一次不會讓它提早結束 |
| 用量查不到（沒登入、斷網） | **打** | 寧可多花 $0.00025，也不要漏掉一次該做的刷新 |

執行紀錄寫在 `%LOCALAPPDATA%\ClaudeTimerResetter\run.log`，主控台下方也看得到最近 20 行。

## 命令列工具

不想開 GUI 的話，`scripts\` 底下這兩個 `.bat` 是同一套核心的命令列版本：

```bat
scripts\usage.bat               :: 只看用量跟重置時間，一定不花錢
scripts\usage.bat --json        :: 機器可讀

scripts\test.bat                :: 該刷新就刷新，不該刷新就不花錢
scripts\test.bat --json         :: 機器可讀
scripts\test.bat --force        :: 不看用量，一定打
scripts\test.bat --no-wait      :: 該等的時候不原地等，直接結束（排程用）
scripts\test.bat --max-wait 300 :: 最多原地等 300 秒（預設 920）
```

`usage.bat` 為什麼不花錢：它打的是 Claude Code 自己 `/usage` 用的那支端點
（`GET /api/oauth/usage`），用本機 `~/.claude/.credentials.json` 裡的 OAuth token，
純 HTTPS GET、不經過模型，想查幾次都行。

**結束碼**（排程／腳本可以直接判斷 `%ERRORLEVEL%`）：

| 碼 | 意思 | 該做什麼 |
|---|---|---|
| 0 | 可用 | — |
| 1 | 呼叫失敗（額度用完 / 逾時 / 模型錯誤） | 可以重試 |
| 2 | 找不到 `claude` 執行檔 | 裝官方 Claude Code |
| 3 | 未登入 / 認證失敗 | 執行 `claude` 登入 |
| 4 | 環境沒裝好 | 跑 `scripts\setup.bat` |

「沒刷新」不是錯誤：`--json` 的 `action` 欄位會是 `refreshed` / `skipped` / `waiting`
三者之一，三種都回結束碼 0。要區分「有沒有真的打」請讀 `action`，不要讀結束碼。

## 疑難排解

| 現象 | 多半是 | 怎麼辦 |
|---|---|---|
| 按「安裝」跳「開發模式」 | 現在是用原始碼跑的 | 先 `scripts\build.bat`，用 `dist\ClaudeTimerResetter.exe` 安裝 |
| 紀錄一直是 `[SKIP]` | 正常。視窗已經在跑，這次不打才對 | 想確認真的會打，可以用 `scripts\test.bat --force`（會花 $0.00025） |
| 紀錄出現 `[WAIT]` | 觸發時剛好接近重置點 | 正常，下一輪 tick 會重新判定 |
| 紀錄出現 `exit 3` / 未登入 | OAuth token 過期 | 開一次 Claude Code，它會自動換新 |
| 完全沒有紀錄 | 排程沒裝成功，或裝的是常駐模式但沒在跑 | 主控台上方「目前狀態」會直接寫現在裝的是哪一種 |
